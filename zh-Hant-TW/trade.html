PhoenixTrade 玩家對玩家交易

雙方面對面的安全交易：把物品放進交易介面自己一側，雙方確認 → 5 秒倒計時 → 成交交換。任一方提前關閉介面即取消並全額返還。可選支援 Vault 金幣交易。

玩家玩法全流程​

1️⃣ 發起交易（三種方式）​

方式操作
潛行右鍵蹲下 + 右鍵點選目標玩家（預設開啟）
命令/phoenixtrade sendtrade <玩家名>
強制（管理員）/phoenixtrade trade <玩家1> <玩家2>

發起後對方會收到一條可點選的聊天訊息「[點選接受]」，點選即進入交易（30 秒內有效，重複發起有冷卻）。

拒絕打擾

不想被交易？/phoenixtrade toggle 一鍵關閉交易請求（狀態會儲存，重進伺服器依然生效），或用 /phoenixtrade toggle false 明確關閉、true 開啟。

2️⃣ 交易介面操作​

介面為 54 格雙欄：

# # # # @ # # # #
# S S S @ T T T #     S = 發起者格子（左 4 列）
# S S S @ T T T #     T = 接收者格子（右 4 列）
# S S S @ T T T #     @ = 分隔板（顯示雙方需支付金額）
# M M M M @ M M M #   M = 金幣按鈕（裝了 Vault 才顯示）
# _ R R R _ R R R #   R = 確認按鈕（左右各 3 格等價）

操作規則：

  1. 把想交易的物品放進自己一側（只能操作自己的格子；shift 放置與雙擊吸收被禁止，物品需逐個放取）；
  2. 點底部自己的確認按鈕：確認後自己的物品鎖定（再點一次可撤回）；
  3. 對方任何改動（物品/金幣報價）都會重置你的確認狀態，介面會提示，請重新檢查後再確認；
  4. 雙方都確認後進入 5 秒倒計時：確認按鈕變成藍色並顯示倒數數字（5→1），期間再點一次確認按鈕 = 撤回；
  5. 倒計時結束自動成交：物品互換 + 金幣淨額結算，雙方收到成功提示與音效；
  6. 倒計時中直接關閉介面 = 取消交易（雙方物品全額返還）。

3️⃣ 金幣交易​

  • 金幣按鈕左鍵加、右鍵減，每按一次增減對應檔位金額（預設 1000 / 10000 兩檔，最多 4 檔）；
  • 報價顯示在中間分隔板上（XX 需支付: xxx）；
  • 支援負數報價（需開啟 Allow-Negative）：負數等價於要求對方付錢；
  • 成交時按淨額單筆轉賬：例如你出 5000、對方出 3000，實際只發生一筆「你→對方 2000」的轉賬；
  • 結算前會再次校驗雙方餘額，餘額不足或經濟外掛拒絕 → 交易取消、物品全額返還（物品絕不動）。

4️⃣ 沙盒測試（管理員）​

/phoenixtrade test [虛擬玩家名]：管理員單人操作雙方區域的完整流程演練——不轉移物品、不扣款，用於上線前檢查介面與配置。

命令一覽​

命令許可權說明
/phoenixtrade-幫助
/phoenixtrade sendtrade <玩家>phoenixtrade.sendtrade發起交易請求
/phoenixtrade accept [玩家名]phoenixtrade.accept接受請求（只有一條時可省略名字）
/phoenixtrade toggle [true\|false]phoenixtrade.toggle開關接收交易
/phoenixtrade trade <玩家1> <玩家2>phoenixtrade.trade（OP）強制開啟兩人交易
/phoenixtrade test [虛擬名]phoenixtrade.test（OP）沙盒交易
/phoenixtrade reloadphoenixtrade.reload（OP）過載配置（會中斷所有進行中交易）

配置詳解（config.yml）​

Trade:
  # 成交前的倒計時秒數（介面按鈕會顯示倒數數字；上限 64）
  Wait-Time: 5

  Economy:
    Enable: true            # Vault 金幣交易總開關（false 則金幣按鈕不顯示）
    Allow-Negative: false   # 允許負數報價（負數 = 要求對方支付）
    Amounts:                # 金幣按鈕檔位，從小到大，最多 4 個
      - 1000
      - 10000

  Triggers:
    Shift-Right-Click: true # 蹲下右鍵發起交易

  Safe:
    Damage: false           # 交易期間玩家免傷
    Move: false             # 交易期間禁止移動/被推動

  Item-BlackList:           # 物品黑名單（確認時校驗，命中則無法確認）
    Enable: false
    Lore:                   # 描述包含匹配（任意一行命中即攔截）
      - "禁止交易"
    Name:                   # 名字包含匹配
      - "XXX"
關於 NBT 黑名單

原版 GoodsTrade 支援 NBT 黑名單；Minecraft 1.21 起物品使用 Data Components 儲存，已沒有可按路徑匹配的裸 NBT，因此 PhoenixTrade 移除了該功能。名字/描述黑名單保留，配合 NeigeItems 等外掛的「繫結」類描述即可實現同類效果。

介面自定義（view.yml）​

plugins/PhoenixTrade/view.yml 可改每個按鈕的材質 / 名字 / 描述 / 自定義模型資料，不配置的鍵用內建預設：

button:
  "#":                      # 背景填充
    material: black_stained_glass_pane
    name: " "
    lore: ["&7"]
  "@":                      # 中間分隔板（金幣資訊由外掛追加）
  "F":                      # 發起者確認按鈕
  "F:Yes":                  # 發起者確認後
  "T":                      # 接收者確認按鈕
  "T:Yes":                  # 接收者確認後
  "Wait":                   # 雙方確認後的倒計時按鈕（數量=剩餘秒數）
  "CancelReady":            # 倒計時中對方撤回後顯示的按鈕
  "Money":                  # 金幣按鈕通用樣式（%amount% 替換檔位金額）
    name: "&6調整金幣: &e%amount%"
    lore:
      - "&a左鍵: 增加 %amount%"
      - "&c右鍵: 減少 %amount%"
  "Money-1":                # 單獨覆蓋第 1 檔
  "Money-2":
  "Money-3":
  "Money-4":

安全機制清單​

機制說明
一側隔離只能操作自己一側的格子，對方格子點選直接攔截
鎖定自己確認後物品與金幣報價鎖定，需撤回才能改
確認重置對方改動任何內容 → 雙方確認狀態清零，強制重新檢查
倒計時撤回倒計時中再點確認 = 撤回；對方會看到「對方取消」按鈕
黑名單確認時校驗物品黑名單，命中禁止確認
餘額終審倒計時結束成交時再次校驗雙方餘額，失敗則整筆取消返還
回滾金幣先扣後轉，入賬失敗自動回滾扣款（物品尚未移動）
關閉即取消倒計時中關介面 = 取消；游標上的物品也會被收回揹包
自交易攔截不能對自己發起交易或強制開啟自我交易

資料與佔位符​

  • 玩家的 toggle 狀態儲存在 plugins/PhoenixTrade/data.yml；
  • %phoenixtrade_stats% → 該玩家是否接受交易（true / false），可配合選單/計分板提示。
